# Changelog

All notable changes to VaultReader. Most-recent first.

## v0.1.1 — 2026-10-09

Security fix release. Upgrade if teammates or share links can write to your vaults.

**Security**
- **Writes to hidden (dot) paths are refused.** Any write whose cleaned vault-relative path has a segment starting with `.` (`.git`, `.obsidian`, `.trash`, …) now gets `403` ("hidden paths … are not writable"), whatever `rw_paths` say. Before, a user allowed to write a folder could write `.git/hooks/…`, `.git/config` or `.obsidian/plugins/…/main.js` inside it, code that a host-side git script or Obsidian desktop then runs. The check sits in the writable-path test used by every write: note create/save/delete, move (both ends), folder create/delete/rename, image upload (note path and written file), attachment delete, trash restore (destination), editable share creation and share-link saves. The trash keeps working: VaultReader's own delete, restore and empty code writes `.trash`. Reads are unchanged.

**Changed**
- **DOCX cover placeholders match fewer style names.** On a title page, a paragraph style starting with `CoverTitle` gets the note title and one starting with `Date` (other than Word's built-in `Date`) gets today's date. A content control tagged exactly `Title`, or starting with `CoverTitle`, gets the title, and one tagged exactly `Date` gets the date. Other `Title…` keys such as `TitlePageBackground` or `title-logo` are no longer overwritten, and tags such as `DateFormat` are left alone.
- The container image ships `LICENSE` and `THIRD_PARTY_NOTICES.md` in `/usr/share/doc/vaultreader/`.
- Docs: `docs/team-instance.md` warns against host git scripts, Obsidian plugins and agent instruction files (`CLAUDE.md`, `AGENTS.md`) in folders teammates can write. `SECURITY.md` no longer claims share links are signed; they are bearer tokens. Copyright line added to README and third-party notices.

## v0.1.0 — 2026-10-09

First public release of VaultReader: a self-hosted, read/write web app for Obsidian-style markdown vaults, published as a multi-arch image at `ghcr.io/joaompfp/vaultreader`. The entries below summarise what changed on the way to this release.

**Added**
- **`demo_mode`** config option: `/api/instance` reports it and the UI shows a dismissible "Public demo — changes are reset every hour" banner.
- Community files: `CONTRIBUTING.md`, `SECURITY.md`, issue and pull-request templates.
- **`export_docx` feature**: DOCX export (and its template listing) is on only when `officecli` is on PATH at runtime and not switched off in `features`; otherwise both routes 404 and the UI hides the export entries.
- **Docs**: rewritten README (quick start, team-instance summary, dated comparison table), new `docs/team-instance.md` (second container, forward-auth with Authelia or oauth2-proxy, audit log format, per-author git history recipe), README images in `docs/img/` generated by `make screenshots` (`scripts/screenshots.mjs`, Playwright against the demo vault). The demo vault gains a small `Projects/` folder.
- **Multi-arch image** (linux/amd64 + linux/arm64) with a SHA-256-verified officecli download, a `Makefile`, GitHub Actions CI and a tag-triggered release workflow publishing to `ghcr.io/joaompfp/vaultreader`.

**Security**
- **Writable-path check judges the cleaned path**: `rw/../ro` no longer passes as being under `rw`.
- **Folder rename checks writable paths** on both the source and the destination, as move already did.
- **Editable shares honour writable paths**: a writable share can only be created for a writable path, and each save through it re-checks the path.
- **Emptying the trash checks writable paths**: only entries whose original path is writable are deleted, for a single entry and for empty-all.
- **Upload checks the written path**: the image lands in `<note dir>/attachments/`, and that path must be writable, not only the note path.
- **Share-link saves ignore `Remote-User`**: `/share/` routes run without forward-auth, so a client could put any name into the audit log with a forged header. Changes made through a writable share link are now recorded as user `share`.
- **Raw vault files are never content-sniffed**: `/api/file`, share files and WebDAV send a server-chosen `Content-Type` with `nosniff`, and sandbox everything but media and PDF.
- **Note HTML is sanitised with DOMPurify** before it reaches the page (fails closed).
- **The SPA shell sends a Content-Security-Policy**, plus `nosniff` and `Referrer-Policy: same-origin`.

**Fixed**
- **Path-style wikilinks count as backlinks** and graph edges (`[[folder/note]]`, not only `[[note]]`).
- **Mermaid edge labels** render with their text instead of as empty boxes.
- Callouts written the usual Obsidian way (`> [!info] Title` with the body on the next `>` line, or `> [!warning]` with no title) now render as callouts; before, only a title followed by a blank `>` line worked, and the untitled form used the body as its title.
- Closing the graph while it is still animating no longer throws `Cannot read properties of null (reading 'zoom'/'animate')`: pending layout/label timers are cancelled on close.
- Proxy peers are parsed with `net.SplitHostPort`/`netip`, so IPv6 (`[::1]:port`, ULA) peers are trusted correctly in the rate limiter and share-URL derivation.
- `base_path` rewriting is limited to `<head>` and the editor bundle tag (inline JS is never touched) and is computed once at startup; the WebDAV handler is built once.
- Release workflow: exact changelog heading match (v1.0.1 vs v1.0.10), pre-release tags (`-`) do not move `latest` and are marked as pre-releases, re-runs are idempotent.

**Changed**
- **`share_base_url` is derived when unset**: `<scheme>://<host><base_path>/share/` from the request (scheme from `X-Forwarded-Proto` when the peer is a trusted proxy, else the connection's TLS state). `/api/instance` returns the derived value. Previously the default was a hardcoded host; set `share_base_url` explicitly to keep a public alias such as `https://example.com/notes/`.
- **DOCX title pages are template-generic**: any template with a `<w:titlePg/>` title page keeps it; a title-page paragraph whose style ID or content-control tag (case-insensitive) equals or starts with `CoverTitle`/`Title` gets the note title, one starting with `Date` gets today's date. Word's built-in `Title`/`Date` paragraph styles are not placeholders (exact style IDs are skipped; content-control tags with those values still count). Templates without a title page get no substitution. Previously this only applied to templates under a specific folder with specific style names.
- **Vault order is configurable**: new optional `vault_order` (vault names listed first, the rest alphabetically). The built-in order list is gone; without `vault_order` vaults are alphabetical.
- Share page footer links to the project repository.
- Go module path is `github.com/joaompfp/vaultreader`.
- Tests, docs and examples use neutral names (`team`, `alice`/`bob`, `*.example.com`).

## 2026-10-09 — CSP on the SPA shell + outline crash fix

**Security**
- `/` and `/n/*` now send a `Content-Security-Policy` (`connect-src 'self'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'self'`; scripts still need `'unsafe-inline'`/`'unsafe-eval'`), plus `X-Content-Type-Options: nosniff` and `Referrer-Policy: same-origin`. Second layer behind DOMPurify. See `docs/security.md`.

**Fixed**
- **Team instance: no more `/api/sync-status` 404 + `stats:` console error on load.** `refreshStats()` fetched sync status unconditionally (and its 404 made the whole stats load fail, so the note count stayed 0); sync status is now only fetched via `refreshSyncStatus()` when `feat('sync_status')`.
- **Rate limiter no longer breaks image-heavy notes.** GET/HEAD of `/api/file`, `/api/vault-icon` and embedded static assets skip the 240 req/min/IP limiter (read-only, cacheable); a note with ~150 embeds used to 429 its own images and then the app's API calls. Mutating `/api/*`, `/share/*`, `/webdav/` and the shell stay limited.
- **Red "Cannot read properties of undefined (reading 'after')" banner** when opening notes whose raw-HTML `<h1>`–`<h3>` headings repeat (e.g. pasted tables with repeated section headers). Goldmark gives raw HTML headings no id, so the outline's `id:text` x-for key collided, and Alpine 3.14's x-for crashed on the duplicate key — then kept erroring on later navigation (Back/Forward). The outline is now keyed by position.
- **Outline works for raw-HTML headings.** Id-less `<h1>`–`<h3>` get a positional `h-<index>` id in the rendered preview (and in the outline), so clicking them scrolls and scroll-spy highlights them; no row is marked active before the first scroll-spy hit.

## 2026-10-09 — Team instance

A colleague can now edit one shared folder (e.g. `work/team`) collaboratively without seeing anything else. Model: **a second container on the same image** with a physically isolated mount, not per-user ACLs.

**New**
- **Per-instance config** (`config.go`): `require_user`, `share_base_url`, `default_note`, `features.{shares,share_writable,webdav,sync_status,trash_empty}`. Defaults reproduce the old behaviour; a disabled feature's route returns 404; an unknown feature key fails startup. Replaces the hardcoded share prefix and the hardcoded default note in `index.html`.
- **Identity** (`identity.go`): `Remote-User` is read for attribution; with `require_user: true` requests without it get 401 (`/share/*` and `/health` exempt). Unauthenticated on the main instance (attribution only).
- **`GET /api/instance`** (version, user, features, rw_paths, share base URL, default note); the SPA hides disabled UI and shows user + build in the footer. `/health` now returns `{"status":"ok","version":"<sha>"}`.
- **Audit log** (`audit.go`): append-only `appdata/audit.jsonl` (save/create/upload/move/delete/restore/share/revoke). Share entries record `created_by`. In the reference deployment a host-side timer (every 5 min) turns the logs into per-author `vr(<user>)` git commits; remaining changes are committed as the fallback author. It stages only files `git status --porcelain -z` reports, so vanished or ignored paths cannot wedge a run.
- **30 s stat rescan** (`rescan.go`): edits made outside the app (Obsidian, Syncthing, the other instance) reach search/backlinks without a restart.
- **Open-note freshness** in the UI: `GET /api/note?...&meta=1` returns `{mtime,size}`; the page re-checks on focus and every 60 s, reloads a clean preview silently, and warns (never overwrites the buffer) when you are editing.
- **Single deploy entry point** (in the reference deployment): a script stamps the git SHA, builds once and recreates both containers. `go test` runs in the Docker builder stage. A health check alerts (never deploys) on image drift between the two containers (`/health` reports the version).
- **Infra**: the team container sits on its own Docker bridge (off the shared proxy network); Authelia rules for the team group, a public `/share/` bypass for the team site, and a `deny` wall for the `external` group on every other host of the domain. See `docs/authelia.md`.

**Fixed (security)**
- **Trash restore** accepted arbitrary paths: it now only takes `.trash/<name>`, validates the decoded destination with `safePath` and requires it to be writable.
- **DOCX template listing** scanned ancestors outside the vault for `path=../..`; ancestors are now confined with `safePath`.
- **`.trash` search leak**: the index and rescanner skip every dot-directory, so soft-deleted notes no longer appear in search, graph or backlinks.

**Fixed (final review)**
- **Stored XSS via note HTML** (critical): note HTML reached `x-html` unsanitised, so a note written on the team instance could run script on the main instance. Every vault-derived HTML sink now goes through vendored DOMPurify (`static/purify.min.js`, fails closed); Mermaid runs `securityLevel: 'strict'` and shows parse errors as text; raw `.html/.htm/.xhtml/.svg/.xml` files are served with `Content-Security-Policy: sandbox` and every raw file with `nosniff`; the share page gets a nonce-only `script-src` CSP and an escaped title.
- **Trash restore** no longer overwrites a note recreated at the original path: `409 a note already exists at the original path`.
- **Conflict detection** is exact: PUT `/api/note` 409s whenever `ifMTime` differs from the on-disk mtime (the 1-second slop let a concurrent write be overwritten), and the open-note freshness check treats any mtime difference as a change.
- **Committer**: resets its offset when `audit.jsonl` shrinks (rotation/truncation), runs `git reset -q` before each window so pre-staged files are not swept into an author's commit, and uses `GIT_LITERAL_PATHSPECS=1`. `work/.gitignore` ignores Syncthing and `*.tmp-vaultreader` temp files.
- **Config**: `config.json` is decoded strictly — an unknown key (e.g. `require_usr`) fails startup.
- **Shares**: the share popover and Settings → Shared list show `by <user>` (`created_by`); the share page says "Editable" only when the share is writable *and* `share_writable` is enabled.
- **Tests** pin `require_user` edge cases (`//api/vaults` 401, `/share/../api/vaults` 301, POST without user 401).
- **Infra**: the team container runs with `no-new-privileges`; its `/share/` router uses a public rate-limited middleware chain (rate limit + public headers).
- **Rescan**: the rescanner snapshots before the startup index build, so files edited during the build are re-read on the first pass.
- **Raw-file content sniffing** (XSS): `/api/file`, `/share/<token>/file` and direct file shares now always set their own `Content-Type` (hardcoded media/PDF map; text-like files as `text/plain`, the rest `application/octet-stream`) and sandbox everything except media and PDF, so a `.md` or extensionless file starting with `<!--`/`<div` can no longer be sniffed into same-origin HTML; the share page CSP adds `frame-src 'none'; child-src 'none'`.
- **WebDAV sniffing**: `/webdav/` GET/HEAD use the same server-chosen `Content-Type` as `/api/file`, and every WebDAV response carries `nosniff` + `Content-Security-Policy: sandbox`; vault-icon responses send `nosniff`.

**Changed**
- Index now follows symlinked files (symlinked directories are still not followed) and keeps a note in the index on a transient read failure instead of evicting it.
- The walker prunes `node_modules` and `.sync-conflict` directories.
- Docs: `security.md` (team model, audit log), `configuration.md`, `api.md`, `authelia.md` (team instance), `CLAUDE.md` refreshed (file map, deploy, image, tests).

## 2026-05-27 — fix(mobile): teleport share popover to body

The share/export popover was invisible on Android Chrome and iOS Safari — the popover rendered at the right viewport coordinates but its painting layer got clipped to `#toolbar`'s content box. The toolbar combines `overflow-x:auto; overflow-y:hidden` with `-webkit-mask-image` on mobile, and that combo defeats `position:fixed` escape on WebKit/Blink in spite of what the spec says.

Fix: wrap `.share-pop` in `<template x-teleport="body">` so Alpine moves it out of the toolbar at runtime. The popover keeps the same Alpine scope (`sharePopoverOpen`, `noteShares()`, `@click.outside`) but is now a direct child of body, with no overflow/mask ancestor to clip it.

## 2026-04-30 — Stage 1: backend modularization

`main.go` (3,588 lines, single file) split into 18 focused `package main` siblings — pure organisational change, runtime byte-identical (Go's package scope concatenates files at compile time, so the resulting binary is the same):

```
main.go           139  (was 3,588 — flag setup + mux + main() only)
data.go           100  shared types, regexes, goldmark init, embed.FS
http.go            98  gzip middleware, JSON helpers, rate limiter
admin.go          180  server struct, AdminConfig, config persistence, admin endpoints
markdown.go       339  rendering, embeds, wikilinks, callouts, frontmatter
index.go          206  NoteIndex methods + helpers (buildAll, resolve, getBacklinks)
search.go         370  query operators, parseSearchQuery, searchVault
notes.go          764  note + folder CRUD, save, upload, search HTTP, resolve, templates, backlinks
files.go          184  buildTree, handleFile, handleVaultIcon, vaultPath, safePath
vaults.go          68  vaultOrder, handleVaults, handleTree, handleIndex
shares.go         461  ShareEntry, ShareStore, share handlers + share-page renderer
trash.go          191  trash naming, list/restore/empty
attachments.go    194  AttachmentItem/Ref, handleAttachments, refcount
stats.go           71  VaultStat, StatsResponse, handleStats
sync.go            69  Syncthing status (TLS-insecure for self-signed)
tags.go           118  tag aggregation across all vaults
graph.go          175  handleGraph (vault/folder/ego scopes for cytoscape)
webdav.go          37  read-only WebDAV mount with method allowlist
```

**Driver:** future feature velocity. Each file now answers one question (where does sharing live? `shares.go`. Where's wikilink resolution? `markdown.go`). Adding a feature touches one focused file ≤500 lines instead of scrolling through `main.go`.

**Verification:** every endpoint smoke-tested after every commit; final integrated smoke test exercises all 14 module surfaces (vaults, writable-paths, stats, note, search, graph, tags, attachments, trash, templates, sync-status, shares, file/icon, traversal-block, webdav, /, /health) — all passing. Baseline `/api/vaults` byte-identical at every commit.

**Stage 2 (frontend modularization) was attempted and abandoned 2026-04-30.** The progressive-override / ES-modules approach raced Alpine 3.x's auto-bootstrap — by the time the mixin module graph finished loading, Alpine had already constructed the component from the (now-incomplete) inline factory. Sidebar broke (file icons rendered as literal "undefined"). All Stage 2 commits were reverted before reaching `main`; the broken `refactor/frontend-modules` branch was deleted. The inline `vaultApp()` factory remains in `static/index.html`, organized into ~50 well-named sections via comment dividers.

## 2026-04-29 — Shared-note image rendering

- **Fix: images broken in shared notes accessed via `/notas/<token>` proxy alias.** The rewriter was emitting absolute `/share/<token>/file?…` URLs; on the public apex host (e.g. `example.com`) the `/share/*` path has no Traefik route, so every embed 404'd. Switched to path-relative URLs (`file?path=…` + `asset?name=…`) anchored to a `<base href="<token>/">` tag. Works under both `/share/<token>` and `/notas/<token>` without the server needing to know the proxy prefix.
- **Plain markdown images now resolved against the note directory.** Previously only Obsidian wikilink embeds (`![[img.png]]`) reached the share-file route — `![alt](sub/img.png)` syntax leaked the literal `sub/img.png` href, which the browser tried against `/notas/...` and 404'd. Now both forms route through `file?path=…`. Fixes embeds in notes that use vanilla markdown image syntax (e.g. converted-from-PDF reports).

## 2026-04-29/30 — Polish wave (Tiers 1–4)

A second wave of work driven by daily-use feedback. Twenty-plus features and fixes across a single user session, mostly small and ergonomic. Rolled out in four "tiers" (the planning rationale is captured in commit messages).

### Graph view — visual + interaction overhaul
- **Switched layout from `cose` (compute-then-place) to `cola` (live force simulation)** via `cytoscape-cola`. The graph now visibly settles from chaos over a few seconds; dragging a node ripples through the rest of the graph in real time. Bundle: +78KB cola + 22KB cytoscape-cola.
- **Live reflow on drag** — `grab`/`free` events restart cola for 1.5s, so the graph keeps wobbling for a couple of seconds after you let go. Inertia, basically.
- **Moebio-inspired visual polish**: smaller nodes (5–14px) with text-opacity hidden by default, curved bezier edges that are visible against dark backgrounds, hover-to-light-up-neighborhood with rest-fade-to-0.12, center node rendered as an outlined accent ring instead of a solid red blob.
- **Three scope modes** with a clickable scope-breadcrumb: all-vaults, single-vault, **folder-scoped** (`?folder=…`), **ego graph** (`?center=vault:path&depth=N`, 1–5 hops via outbound + inbound). Toolbar graph icon picks the smallest meaningful scope based on what's open.
- **Per-graph depth ± controls** when in ego mode. Shift-click any node to re-center the graph there; Cmd/Ctrl-click opens the note in a new tab.
- **Zoom-aware label visibility** — labels hidden until rendered font ≥ ~14px so default-zoom views are geometry-only, hover/lit nodes always show labels.

### Editor UX (Tier 1)
- **Search ranking** — title-match (×20) > filename-match (×5) > body-occurrence (×1, capped 5), plus 0–3 recency boost over 30 days. Top 20 by score per vault. Old behavior kept the first 20 in filesystem order; recently touched notes used to sink under stale archives.
- **Alt+← / Alt+→** for back/forward through visited notes (wraps `window.history.back/forward`). Skipped in text inputs / editor.
- **Paste/drop image in preview mode** — uploads + appends `![[…]]` at end of note + saves with conflict detection + re-renders. No edit-mode switch needed. Honors `isWritable`.
- **Rename warning** — new `/api/backlinks` endpoint; `promptRenameNote` checks before showing the rename input. If any notes link to it, surface a danger modal listing up to 5 affected titles + "Rename anyway".

### Editor UX (Tier 2)
- **Right-click on `[[wikilink]]`** in preview → context menu: Open · Open in new tab · Reveal in sidebar · Copy wikilink · Copy URL. Missing-link spans get "Create" + "Copy as text" instead.
- **Reveal in sidebar** via `Ctrl+Shift+L` or context menu. Switches to the note's vault, navigates `cwd` to its parent folder, smooth-scrolls the row into view.
- **Daily note opens in edit mode** with cursor at EOF when freshly created (existing dailies open in preview as before).
- **Whitespace normalization on save** — backend `saveNote` strips trailing space/tab per line and ensures exactly one trailing newline. Reduces git-diff noise when the same vault is edited from multiple tools.
- **Drag-and-drop sidebar items** to move into folders. File rows + folder rows are draggable; folder rows + the `..↑` row are drop targets with a dashed-accent outline on hover.

### Editor UX (Tier 3)
- **Undo toast for delete** — bottom-right toast for 6.5s after soft-delete. Click Undo → restores from `.trash/`. Bulk-aware (one combined toast for the whole batch).
- **Search across attachment names** — `/api/search` includes image filenames as `kind: "image"` results, scored lower than note matches. UI shows 🖼 prefix; click opens in a new tab.

- **Note templates** — `<vault>/templates/*.md` enumerated via new `/api/templates`. "+ New" → "From template…" picker. Placeholders `{{date}}`, `{{date:FMT}}` (custom YYYY/MM/DD/HH/mm/ss), `{{time}}`, `{{title}}` expand on creation. Drops user into edit mode at end of file.

### Editor UX (Tier 4)
- **Search operators**: `tag:foo` / `path:foo` / `title:foo` / `modified:>7d` / `modified:<2026-01-01`. AND together. Plain text after operators acts as the body substring filter as before. Operator-only queries (e.g. `tag:work modified:>7d`) return everything matching, sorted by recency.
- **Mermaid + KaTeX in shared notes** — both were previously not rendered at all (handleShareView didn't load the libs, AND Authelia would have blocked `/static/` even if it had). Fixed via new `/share/<token>/asset?name=…` route under the existing share-bypass; conditional script-tag injection (only if the page actually contains `language-mermaid` or math delimiters); KaTeX CSS font URLs rewritten to absolute share-asset URLs. Strict allowlist + extension check prevents leaked tokens from fetching arbitrary static files.

### Bugfixes
- **Trash naming overhaul (`VRTRASH_<base64>_<unix>` scheme)** — legacy `__→/` round-trip corrupted any file whose original basename contained `__` or started with `_`. New scheme encodes the full vault-relative path in base64-url, eliminating the entire class of round-trip bugs. Legacy entries keep working via `legacyDecodeTrashName` fallback.
- **Modal z-index 500 → 1100**, was rendering behind settings (`800`), making the "Revoke all share links?" confirm invisible.
- **`revokeAllShares` had `confirmOnly: false`** so the input box was visible on a pure-confirm danger modal — tab-to-confirm enforced "Name cannot be empty". Set to `confirmOnly: true`.
- **Bulk revoke** was using `POST` against a `DELETE`-only handler; replaced with batch endpoint `DELETE /api/shares/revoke-all` (no per-token rate-limit hits either).
- **Misleading "all vaults are read-only"** copy when `rw_paths` was empty — replaced with a hint that suggests what to add.
- **Goldmark HTML-escapes `&` to `&amp;`** in attribute values, breaking the regex that rewrote `/api/file?…` URLs to `/share/…/file?…` for share images. Now decodes the entity before parsing.
- **Tag-operator strict matching** — `tag:london` initially didn't catch `london-2026`; relaxed to substring match (still respects exact + hierarchical descendant rules first).
- **Outline class binding** rendered `[object Object]` because Alpine's `:class="[a, {b: c}]"` array+object form silently degrades in this Alpine version. Switched to string concat.
- **Frontmatter chip click race** — clicking a chip set `searchQuery` then opened the overlay, but the `$watch('searchOpen', …)` reset `searchQuery = ''` on open. Reordered: open first, set query in `$nextTick`.
- **Wikilink popup label visibility** in the cola layout regressed because `min-zoomed-font-size` was unreliable post-cola; switched to a JS zoom-event handler.
